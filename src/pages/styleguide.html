Styleguide

Zipli marketing site

Every element below uses the classes that already ship in zipli.webflow.css. Copy the markup straight into a new page in src/pages/. Do not invent new class names for something that already exists here.

Scaling: above 991px the body font-size is 0.8333vw, so 1em is 1/120th of the viewport width and the whole layout scales with the window. Below 991px it locks to 16px. Size everything in em or it will not scale with the rest of the page.

Layout

Every section follows the same three-level nesting. Start from this when you build a new one.

<section class="my-section">
  <div class="padding-global">              <!-- 2em side gutter -->
    <div class="main-container new-home">   <!-- 90em max, centred -->
      <div class="padding-xlarge"></div>    <!-- vertical rhythm spacer -->
      ...content...
      <div class="padding-xlarge"></div>
    </div>
  </div>
</section>

The three levels never change: .padding-global owns the side gutter, .main-container owns the max width, and spacers own the vertical rhythm. Do not put a side padding on a container or a max width on a section. The full spacing and width scales are in the next three blocks.

This project follows Client-First. A spacer is an empty div that does nothing but create vertical space, and it sets padding-top only, so spacers never collapse into each other. Reach for a spacer before you write a margin.

Modifiers. Gap defaults to 2em, the value the existing help card grid uses. Override with .gap-small (1em), .gap-large (4em) or .gap-xlarge (6em). Vertical alignment is .items-start and .items-center, named that way because .align-center is already taken and means margin auto.

.on-dark inverts the text, .center on a .stat-item centres it, and two modifiers colour just the figure: .lime and .green.

Which of the two depends on the ground, and it is not a preference. Lime on white measures 1.28:1 against the 3:1 that large text needs, so the figure all but vanishes; on the ink section it is 13.9:1. Green is the mirror image: 7.8:1 on white, 2.3:1 on ink. So .lime on a dark section, .green on a light one, and never the other way round. Green is the same accent the CTA label and the read-more link already use, so a coloured figure on a light page is not introducing a new colour.

Logo cloud

For partner, customer and funder marks. Items are sized by height, not width, so marks with different proportions sit on one optical line. That is the thing most logo rows get wrong. Add .tall to a mark that carries a lot of internal padding or a stacked lockup, so it reads at the same weight as a plain wordmark.

There is deliberately no greyscale-to-colour hover. The marks here are already flat black, and that effect is the single clearest tell of a template site. .left aligns the row left instead of centred; .on-dark inverts the marks for a dark section.

Only use .on-dark on a single-colour mark. It works by inverting the image, which is right for a black wordmark like the Helsinki one and wrong for anything with brand colour in it: it would turn the EU flag's blue into orange, which is a trademark problem rather than a styling one. For a colour mark on a dark section, ask the owner for their reversed version instead.

Audience column

The Industries pages have to argue to two people at once: the person who uses Zipli every day and the person who signs for it. The em rule

Every utility on this page is in em. That is not a style preference, it is required. body is 0.8333vw, so em scales with the viewport and rem does not, because html is left at the browser default of 16px.

Fixed, kept here as a record: the export originally had 15 rules using rem at desktop scope, so they held a fixed size while everything around them scaled. .main-button was the clearest case, reading padding: 1em 2rem and mixing both units in one declaration; it now reads padding: 1em 2em. All of them have been converted, and node audit.mjs reports 0 errors. Sixteen rem values do remain in zipli.webflow.css, but every one sits inside a max-width: 991px media query or narrower, where the body font-size is pinned to 16px and rem and em are the same thing. Those are harmless and the audit correctly ignores them.

Deliberate exception, not a bug: h1 is set in fixed pixels rather than em, at font-size: 100px, line-height: 97px and letter-spacing: -8px. It is the one place the site opts out of the scaling rule, and it is the largest type on the page, so it is also the most visible place to opt out. The effect is that the hero headline holds one size while the layout around it grows and shrinks: proportionally large at 1200px and proportionally small at 1900px. Converting it to em is a one-line change but it visibly redraws the hero at most widths, so it is a design decision rather than a cleanup, and it stays as-is until someone makes that call. Do not copy this pattern into new work. Every component on this page is in em.

Adding a page
